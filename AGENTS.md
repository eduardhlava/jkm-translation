# Architecture rules
- Editor contents navigation lives in a UI-only wrapper around BlockEditor with stable block markers and the shared heading-number helper; panel and highlight state never modify document data, collapsed state or pagination fingerprints.
- PDF content images are height-limited with contained aspect ratio, and block containers never flex-shrink, so oversized unbreakable nodes cannot squeeze neighboring text or images.
- PDF preview confirms stale layout fingerprints instead of disabling access; pagination-then-preview passes returned blocks directly to generation to avoid stale React state.
- Pagination measures the real DocumentPdf sequentially; the keep-with-next probe compensates on its outer container, and an unconditional final measurement reports all remaining violations (including too-long tables), so skipped problems cannot appear as success.
- Image-table pagination measures image and table starts separately and escalates from a whole-block break to a transient internal table break; prepared assets preserve the current flag so only tables exceeding a fresh page are classified too long.
- Pictogram wrappers allow page wrapping; inner image and table-row units retain their own non-wrapping behavior so pictograms never force a whole text or table onto the next page.
- Table rows remain string cells: rich cells use an explicit HTML discriminator after the pictogram token, sanitized by shared cell helpers; native Notion annotations carry B/I/U and metadata preserves unsupported indices with a visible-text guard, so legacy plain cells and Notion edits remain compatible.
- Cell merges live in TableContent.merges as rectangles ({r,c,span,rowSpan?}, rows stay rectangular with emptied covered cells); helpers in cellMerges.ts handle normalization, merge checks and row/column remaps, merges persist via LOV block meta (mg/tmg), and a covered cell that comes back non-empty from Notion cancels that merge so no text is lost. PDF renders row groups sharing a vertical merge as one unbreakable guillotine-split View because react-pdf has no rowspan.
- Document header and metadata dialog share one title-update handler that renames the Notion page through updateTitle before updating the local list; printed metadata remains separate to prevent unsynchronized names and PDF changes.
- Structural spacing is represented by a `spacer` block with empty content and a round-trip metadata marker, so JSON and Notion retain document layout independently of visible text.- Notion files DB 'typ'/'stroj' may be select or multi_select: edge functions read them as string[] and pick the write/filter shape from the live DB schema (helpers in supabase/functions/_shared/notion.ts), so a manual Notion type change needs no redeploy.
- Half-width left/right images and the consecutive following text blocks (chain ends at the first non-text block) render in PDF as one unbreakable row plus full-width remainder; the text split is a width-based estimate (src/lib/pdf/imageWrap.ts) because react-pdf has no float.
- Every code change bumps the app version (semver: MINOR for features/visible behavior, PATCH for fixes/minor tweaks, MAJOR for incompatible rebuilds) by prepending/updating the first entry in src/lib/changelog.ts (single source of APP_VERSION and date); user-noticeable changes get a short plain-Czech bullet, cosmetic/refactor changes only bump PATCH (use "Drobná vylepšení a opravy." if no bullet). Done automatically, never asked.
